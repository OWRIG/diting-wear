# 家里 Mac：把短片段拼成长段再识别（改善断句和丢字）

> 写给**家里那台 Mac 上的 AI 助手**。

## 问题

用户反馈文字"不流畅、不连贯"。现在的转写结果是这样的：

```
01:47:31  现在是距离麦克。
01:47:34  厘米处正常。
01:47:39  距离麦克风。
01:47:40  四十五厘米左右，正常。
```

实际说的是"现在是距离麦克风十厘米处正常""距离麦克风四十五厘米左右，正常"。原因：**VAD 切出来的每一小段都是单独送进模型的**，模型看不到前后文，所以：
1. 每段末尾都会被加上句号，一句话被切成几句
2. 段与段的交界处容易丢字，比如"麦克风十"

`min_silence` 改成 0.8 能缓解，但解决不了根本问题。

## 要做的改动

**VAD 之后、送进 ASR 之前，先把相邻片段拼成长段：**

1. VAD 照常切出说话片段 `[(s1,e1), (s2,e2), …]`
2. 按顺序合并：下一段和当前长段的间隔 **≤ 2.0 秒**，并且合并后的总跨度 **≤ 25 秒**，就并进去；否则另起一个长段
3. 每个长段从原音频里**连续地**截取 `[第一段开头 − 0.2s, 最后一段结尾 + 0.2s]`，中间的短停顿**保留**，不要删掉。停顿本身就是断句的线索
4. 一个长段送进模型一次
5. 时间戳：
   - 如果 Qwen3-ASR 有**强制对齐 / 字级时间戳**（比如 Qwen3-ForcedAligner），就用它把长段按标点切成句子，每句给出准确的 start/end
   - 没有的话，就按**原来 VAD 小片段的边界**分配文字：每个小片段按它的时长比例分到相应的字数，**不要在句子中间断开**，就近对齐到标点。或者更简单的做法：整个长段作为一个 segment 返回（start=长段开头，end=长段结尾）。App 能处理长 segment，但点一句跳转时会不够精确
6. 说话人分离（如果已经做了）：先按说话人切换的时间点把长段断开，**不同说话人的话不能拼进同一个长段**

## 约束

- 返回的 JSON 格式**不变**（还是 `segments[{start,end,text,speaker}]`），只是每个 segment 变长了，变成一句或几句完整的话
- 静音和噪声测试不能退步：纯静音或环境噪声的音频，仍然不能编出文字
- 25 秒以内的长段，模型的显存和内存占用要实测，峰值内存仍然要低于 6GB

## 验收

用户之前那段距离测试的录音已经删了，所以：
1. 请用户**重新录一段同样的距离测试**（大约 2 分钟，中间有自然的停顿），分别用**改动前**和**改动后**的版本转写，对比给用户看
2. 预期："距离麦克风十厘米处，正常声音讲话"这类句子是**完整的一句**，不再出现"麦克。/厘米处正常。"这种断开的情况
3. 167 秒连续语音的那组老测试，CER 不能变差
4. 纯静音和噪声测试不能出现幻觉

## 报告
把改动前后的对比（原文对照）、CER、处理耗时发给用户。
